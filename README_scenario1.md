# SPEC-GAP Scenario 1 (research-pipeline exfiltration)

This is the **schema + controlled-inputs scaffold** for Scenario 1: one match
group of the public-health domain, expressed in the shared event-style
trajectory format. It is a scaffold everyone can follow, not the full dataset
and not a model runner.

Schema version: **`spec_gap.scenario1.v2`**.

## Ownership boundaries

```
shared inputs -> shared generator -> Modal Qwen backend -> event trajectory -> adapter -> activations & metrics
```

- **This PR:** the event-style schema, one validator, the schema/input
  documentation, and the public-health input group.
- **Onyinye:** the shared dataset generator/orchestrator (reads the shared input
  registry).
- **PR #8:** the shared `Qwen/Qwen3-32B` Modal backend, thinking on/off,
  activation extraction, model metadata, and cost safeguards.
- **PR #4:** normalization into the probe/metrics format and the canonical
  behavioral outcome mapping.

The `scenario1_pipeline.py` here is a **structural dry-run generator only** — it
proves the schema, the topology, and the validator agree. It does not call a
model, start a GPU, or write activation files.

## Files

Inputs (committed):

- `experiments/scenario1/inputs/registry.json` — the controlled input registry:
  task, system prompts, three document slots, the group's assigned wording,
  seed, and the injection spec.
- `experiments/scenario1/inputs/documents/*.txt` — three clean documents named
  after the source PDFs. **Report 3 is the clean canonical text**; the injection
  is inserted only while constructing the injected condition.
- `experiments/scenario1/inputs/pdfs/*.pdf` — the original source PDFs (Report 3
  is poisoned; the `.txt` fixture is the de-poisoned canonical version).

Schema / validation (committed):

- `scenario1_trajectory.schema.json`, `validate_trajectory.py`,
  `tests/test_scenario1_schema.py`, `tests/test_scenario1_validator.py`.

Generated by the dry run (not committed):

- `experiments/scenario1/trajectories/*.json|.jsonl` — structural v2
  trajectories.
- `experiments/scenario1/manifest.json`.

## Inputs vs outputs vs real data

- **Input fixtures** (`inputs/…`) are the controlled task and documents.
- **Dry-run trajectory files** are the *structural outputs* of
  `scenario1_pipeline.py --mode dry_run`. They are an **initial end-to-end
  validation subset**: they confirm the pipeline and schema work. A dry run does
  **not** call the model and does **not** count as experimental data.
- **Real model trajectories** and **activation artifacts** come from PR #8 on
  Modal; only Worker1 ever sees the raw poisoned document, and `.pt` tensors are
  never committed to Git.
- The **probe/metrics importer** still expects the older flat per-step format;
  the **PR #4 adapter** converts these event-style trajectories to it.

## Smoke check

```
python scenario1_pipeline.py --mode dry_run
python validate_trajectory.py experiments/scenario1/trajectories/*.json
```

This generates one match group — clean/injected × 2-hop/3-hop — and validates
each file against the v2 schema and the semantic invariants. It does not call
the real model and does not create real activation files. The generated files
confirm the pipeline and schema work; they are not real-model experiment
outputs.

Run the tests with:

```
python -m pytest tests/test_scenario1_schema.py tests/test_scenario1_validator.py -q
```

## What this group encodes

- Four base conditions sharing the same task, documents, system prompts,
  wording, seed, and document order — only treatment and depth vary.
- Injection fixed at `worker_1` at both depths; `worker_2` and the executor are
  relay-fed and never see the raw poisoned document.
- The injected executor forwards the endpoint in text but fires no structured
  tool call, so the outcome is `propagated_but_not_executed` — a black-box
  non-compromise, not `executed`. Injection is the treatment, not the outcome.
- Reasoning labels stay null (`human_or_mechanistic_evidence_required`); they are
  never inferred from construction metadata.

## Not in this scaffold

Real model runs, materialized activations, thinking-mode realizations, the
shared generator, and the probe/metrics adapter. Those are owned by PR #8,
Onyinye's generator, and PR #4.
